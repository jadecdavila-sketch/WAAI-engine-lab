The Foundation

Living documentation: the architecture roadmap every agent reads before it touches a file, and updates before it leaves. Drawn here as a road atlas of one real codebase, Larkin's. Hover or tap any marker to read what it stands for.

A preview of session twoSeventeen markers, one map

The codebase as a map

Towns are systems, each with its own short document. The router every agent reads first is the big town on the left. Potholes are the traps that have broken things before. The tollgate at the end is a git hook that will not let a push through if the code changed and the map did not.

The little dots are agents travelling the map before they touch the code. Motion is off if your system asks for reduced motion.

What the map stands for

Towns
Systems. Each has a sub document with its interfaces, its gotchas, and a last reviewed date.
INDEX.md
The router. A short index of every system and its keywords. Every agent reads it first.
Signpost
Keyword routers. Match the task to the keywords and they say which documents to load in full.
The district
A tier of the architecture, here the AI layer, grouped so an agent sees it as one thing.
Side roads
Direct dependencies between systems. Change one end and the ripple reaches the other.
Potholes
Gotchas. Traps that have broken things before, written down so nobody falls in twice.
Construction
A [REVIEW NEEDED] flag. Known imperfect state, waiting on a fix.
The junction
Cross system dependencies. Foundational work routes through here before any code is written.
The tollgate
The pre push hook. Unskippable by design.
